Local backend tests run against PGlite's PostgreSQL engine, with serialized test transactions because its socket bridge multiplexes one backend. Production uses normal native PostgreSQL transactions. Native PostgreSQL is a separate required CI gate, not assumed equivalent solely from PGlite results.

SCIM transaction boundary note: an early browser/integration run exposed that returning `reply.send()` from inside the tenant transaction could release the HTTP response before COMMIT completed. The SCIM response path now returns its payload only after `db.tenant(...)` resolves, so a successful offboarding response represents committed membership/session state.

Host live-collaboration note: the final Keycloak regression proved server-side OIDC session deletion and HTTP rejection of the old session. The report did not include a directly observed post-logout WebSocket edit/persistence attempt, so that narrow host observation is not claimed beyond the collaboration server's existing session-recheck behavior and automated coverage.

Browser acceptance ran against the full Docker deployment, using the restricted runtime database account and the Caddy reverse proxy. Two independent signed-in browser contexts exchanged edits; the test also queried canonical API content before opening the second context and checked content after reload. This is one Chromium acceptance scenario, not a complete browser or accessibility audit. Local Chromium could not launch in the managed build environment, so CI supplied the browser evidence.

The successful CI run contains a browser-results artifact with home, editor, table, board and mobile screenshots. Desktop layouts and the mobile screenshot were visually inspected. Automatic approval review blocked adding those images to the public source repository because they contain workspace/user labels; they are not included in this documentation commit.

## Suggested next acceptance slice

With native PostgreSQL/container/browser gates, independent WSL2 deployment/recovery, real Keycloak login/logout acceptance, and SCIM Users/Groups lifecycle now passing under `workspace_runtime`/`NOBYPASSRLS`, the next identity work should focus on broader provider compatibility and per-tenant IdP/enterprise policy needs rather than expanding directory authority into privileged roles. Trusted TLS is now CI-verified. For deployments choosing S3-compatible object storage, provider acceptance is a deployment-specific host gate; local-filesystem deployments do not depend on it. Operational tenant provisioning is closed and verified. External monitoring/alerts, adversarial security coverage, Chromium + Firefox browser/accessibility, and release-image security are closed and verified. Encryption-at-rest and encrypted-backup hardening are closed and verified. File malware scanning/reject-before-publish is closed and verified. Retained quarantine/CDR remain separate later controls. The next engineering identity gate is per-tenant IdP configuration, issuer/session binding and secret-management isolation.


## Accepted Wave R boundary — W18/W19 and W24-R

Wave R is accepted through PR #162, merged at `377b8a653c49177b6989a8fc7032819adf77719b`. Exact feature head `7a60f7fb3be85d6311d1b11fb76d94b1a169898f` passed full Actions run `37654531459`.

- **W18 interrupted-edit recovery:** bounded device-local recovery exists for unacknowledged collaborative edits, with principal + room/epoch binding, explicit Restore/Discard, bounded retention, canonical-server acknowledgement as the durability boundary, and fail-closed cleanup on logout, ACL loss, authentication/ticket denial, deletion and stale epoch. This remains recovery for interrupted edits, not full offline-first operation.
- **W19 collaboration reliability:** acceptance covers disconnect storms, real writer restart, advisory lease exclusivity, reconnect convergence, revoked offline edits, deleted-resource fail-closed behavior, history restore while reconnecting, stale-room rejection and exactly-once canonical persistence.
- **W24-R collaboration capacity:** the durable run artifact `capacity-results/w24-r-capacity.json` records successful 1/5/10/25-session reconnect scenarios on a 4-vCPU / ~16.8 GB GitHub-hosted Linux runner. At 25 sessions, p50 reconnect completion was 7.659 s, p95 9.374 s and p99/max 9.396 s; collaboration remained healthy with 25 live connections, and PostgreSQL reported zero non-granted locks. This is CI-host qualification evidence only, not a universal production SLO. Full-system W24 remains open for later worker/integration/backup/load qualification.

This acceptance updates the previous offline/scale statement: Workspace now has bounded interrupted-edit recovery and measured single-writer collaboration reconnect evidence. It still does not claim a horizontally coordinated multi-writer architecture or general-purpose offline-first queue.


## Accepted Wave I boundary — W20/W21/W22

Wave I is accepted through PR #165, merged at `90fb1cf841e16fc05a44d35f643df118c164e547`. Exact feature head `4232d4585f6a866589ac43aca9e103d23d9e05b7` passed full Actions run `37678028893`.

- **W20 leased outbox/webhook delivery:** webhook delivery no longer holds a tenant transaction or subscription read lock across outbound HTTP. A worker claims a bounded 30-second lease in a short transaction, sends with no database locks held, and acknowledges only while the lease token still matches. A crashed worker leaves a recoverable lease that redelivers after expiry, so delivery stays at-least-once and receivers must deduplicate event IDs; exactly-once network delivery is not claimed. The accepted signing-rotation contract is preserved: activation still cannot switch the effective secret out from under an in-flight old-secret delivery, now coordinated on the delivery lease, bounded, and failing closed with `409` while a crashed worker holds an unexpired lease, then proceeding once the lease expires. Acceptance additionally covers revoked-subscription lease cancellation and tenant scoping of lease state.
- **W21 current-state reconciliation (audited, not rebuilt):** `GET /api/v1/events/reconcile` with its encrypted tenant/principal-bound cursor was already implemented and documented, including the boundary that it is a keyset read over committed rows and neither change-data-capture, a transactionally consistent snapshot, nor authority to delete stale consumer data. Prior acceptance already covered tamper rejection, cross-tenant and cross-principal rejection, bounded scans, inaccessible-ID non-disclosure, current ACL recheck, scope restriction, grant discovery, revocation, deletion and non-rewinding keyset continuation. The remaining gap was closed by asserting that an authenticated but expired scan cursor is rejected rather than silently resuming a stale pass.
- **W22 versioned typed contract and client:** the external integration contract is machine-readable at `/api/docs` and `/api/docs/json`, and typed client output is deterministically generated from `integrationOpenApi`, committed to the repository and drift-checked as the first stage of `npm run typecheck`. The typed bearer-token `WorkspaceIntegrationClient` builds versioned `/api/v1` requests and surfaces the structured error envelope (status, Workspace `request_id`, message). A guard test pins the external surface to the explicit 16-route integration set so no human or administrative route can leak into it. No embedded credentials and no OpenJM Enterprise AI dependency.

This acceptance updates the previous integration statement: the reconciliation API is now formally accepted rather than pending, and the external contract has a reproduceable generated client. Full-system W24 capacity, W23 recovery automation and the residual W08/W09 operational gates remain open and belong to Wave O.
